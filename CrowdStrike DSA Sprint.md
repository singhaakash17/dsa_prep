The 25-minute rule for every solve-track problem

1. **0–3 min:** restate the problem, ask about edge cases, say brute force and its complexity out loud.
2. **3–6 min:** before any code, write comments: what each variable means (is the end inclusive or exclusive?), what the function returns, and 4–6 lines of pseudocode.
3. **6–20 min:** turn each comment into code, using the matching skeleton. Talk while you type.
4. **20–25 min:** walk through 2–3 inputs by hand: empty, single element, answer in the middle.
5. **Stuck at 12 min:** look up the pattern name only. The timer turns amber.
6. Stopping the clock logs your minutes; then mark Solved, Hint or Redo yourself.
7. **Not done at 25 min:** read the solution and mark *Redo*. Redo it from a blank editor the next morning.
8. Then answer the follow-up in the orange line: CrowdStrike interviewers often push to streaming input or concurrency.

Before you say “done”: no shadowed built-ins (list, dict, id), no variable named l, no leftover prints, never x = x.sort().
